## 2. مسؤوليات الطبقات
- **app:** تهيئة التطبيق والتوجيه وربط مزودي السياق.
- **components:** عناصر واجهة عامة لا تحتوي منطق مجال متخصص.
- **features:** كل مجال وظيفي يحتفظ بمكوناته وخدماته واختباراته.
- **services/firebase:** نقطة موحدة للتعامل مع Firebase.
- **services/ai:** عقد موحد لطلبات التوليد والتحليل واختيار المزود خلف الواجهة.
- **server:** أي عملية تتطلب سرية مفاتيح أو تحققاً موثوقاً من الصلاحيات.
- **types:** تعريفات مشتركة لعقود البيانات والطلبات والاستجابات.
- **docs:** مرجع دائم للفكرة والهيكل والحالة والقرارات.

## 3. قواعد تنظيم الكود
1. لا تضع منطق Firebase داخل مكونات العرض مباشرة؛ استخدم خدمات متخصصة.
2. لا تربط مكونات React بمزود AI محدد.
3. لا تضع مفاتيح سرية في متغيرات VITE_ أو ملفات المصدر.
4. اجعل كل Feature مستقلاً قدر الإمكان وبواجهات واضحة.
5. تجنب تكرار مكونات الواجهة؛ ضع المشترك في components/ui.
6. افصل قواعد التحقق من البيانات عن العرض.
7. أضف اختبارات للمصادقة وصلاحيات المشروعات وحفظ الملفات.
8. لا تنشئ ملفات فارغة لمجرد مطابقة الخريطة؛ أنشئها عند بدء تنفيذ مسؤوليتها.
9. حدّث هذه الوثيقة عند أي تغيير فعلي في بنية الملفات.
10. حافظ على دعم العربية وRTL في كل ميزة جديدة.

## 4. نموذج بيانات مبدئي
    users/{uid}
      profile fields
      createdAt
      updatedAt

    users/{uid}/projects/{projectId}
      title
      description
      discipline
      status
      createdAt
      updatedAt

    users/{uid}/projects/{projectId}/assets/{assetId}
      storagePath
      type
      metadata
      createdAt

هذا تصور أولي قابل للمراجعة قبل اعتماده في Firestore. يجب أن يعتمد الأمان على Firebase Security Rules والتحقق الخادمي، لا على إخفاء المسارات في الواجهة.

## 5. مسارات الصفحات المقترحة
| المسار | الغرض |
|---|---|
| / | الصفحة التعريفية / نقطة الدخول |
| /login | تسجيل الدخول |
| /register | إنشاء حساب |
| /workspace | مساحة الطالب |
| /projects | قائمة المشروعات |
| /projects/:projectId | تفاصيل مشروع |

هذه مسارات مقترحة وليست مسارات منفذة حتى يتم إنشاؤها واختبارها.

- راجع README إذا تغيرت طريقة التشغيل أو الإعداد.
