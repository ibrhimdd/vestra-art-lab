# PROJECT OVERVIEW — VESTRA ART LAB

## 1. تعريف المشروع
VESTRA ART LAB مختبر إبداعي فني رقمي متعدد التخصصات مدعوم بالذكاء الاصطناعي، يستهدف طلاب كلية التربية النوعية، ويجمع بين إنتاج التصميمات الرقمية وتحليلها والتجريب الفني والتعلم القائم على المشروعات.

## 2. الرؤية والأهداف
تمكين الطلاب من تحويل أفكارهم إلى أعمال فنية وتصميمية رقمية، واستكشاف البدائل وتحليل الأعمال وتحسينها، مع بقاء الطالب صاحب القرار الإبداعي.

## 3. المجالات الفنية
1. الملابس والنسيج.
2. التربية الفنية.
3. التصميم الرقمي.
4. الفنون الزخرفية.

## 4. الوظائف الأساسية
- حسابات المستخدمين ومساحة الطالب والملف الشخصي.
- إنشاء المشروعات وتعديلها وحفظ مراحلها ونتائجها.
- رفع الصور والرسومات المرجعية والفيديوهات.
- لوحات الإلهام ومكتبة الخامات واستوديو الألوان.
- مساعد ذكاء اصطناعي للتوليد والتحليل.
- تجربة الملابس الافتراضية.
- التقييم الفني والقياس البحثي والتقارير.

## 5. القرارات التقنية المعتمدة
| المجال | القرار |
|---|---|
| الواجهة | React + Vite |
| النشر | Vercel |
| المصادقة | Firebase Authentication |
| قاعدة البيانات | Cloud Firestore |
| تخزين الصور والفيديو | Cloudinary |
| الذكاء الاصطناعي | Flexible provider adapter |
| اللغة والاتجاه | العربية وRTL |

Firebase Storage غير مستخدم في المعمارية الحالية. لا يوجد PHP أو MySQL ضمن التصميم المعتمد.

## 6. فصل البيانات عن الوسائط
Firestore يحفظ بيانات المستخدمين والمشروعات والبيانات الوصفية وروابط الملفات فقط. Cloudinary يحفظ ملفات الصور والفيديو الفعلية ويقدم روابط HTTPS.

### دورة رفع الوسائط
1. التحقق من تسجيل دخول الطالب ومن نوع الملف وحجمه.
2. الحصول على بيانات رفع آمنة عند استخدام signed upload؛ لا يرسل API Secret إلى المتصفح أبداً.
3. رفع الملف إلى Cloudinary.
4. قراءة secure_url وpublic_id وresource_type وformat وbytes وأي metadata لازمة.
5. حفظ مستند الوسائط في Firestore مع ownerUid وprojectId والرابط ومعرّف المورد والبيانات الوصفية وcreatedAt.
6. استرجاع المستند وعرض الوسائط باستخدام secure_url.
7. عند الحذف، التحقق من الملكية على خادم موثوق ثم حذف مورد Cloudinary وتحديث Firestore.

يمكن استخدام unsigned upload preset مقيد للاختبار أو عند الضرورة، مع تقييد أنواع الملفات وأحجامها ومجلدات الرفع ومراجعة مخاطر إساءة الاستخدام. الأفضل للإنتاج signed upload من خلال خادم أو وظيفة موثوقة.

## 7. الأمان والخصوصية
- التحقق من الصلاحيات في قواعد Firestore والخادم، وليس في الواجهة فقط.
- عدم تخزين مفاتيح API أو Service Account أو Cloudinary API Secret في Git.
- رابط Cloudinary العام ليس بديلاً عن صلاحيات Firestore؛ يجب تحديد سياسة الملفات العامة والخاصة.
- تقييد أنواع الملفات وأحجامها ومعدلات الرفع.
- عدم إرسال أعمال الطلاب إلى مزود AI خارجي دون توضيح مناسب.

## 8. مراحل التنفيذ
1. تأسيس المشروع والهوية والهيكل والتوثيق.
2. الحسابات ومساحة الطالب وإدارة المشروعات.
3. ربط Cloudinary ورفع الوسائط وحفظ metadata وروابطها في Firestore.
4. معمل التصميم ومكتبة الخامات ولوحات الإلهام.
5. الذكاء الاصطناعي للتوليد والتحليل.
6. دمج تجربة الملابس الافتراضية.
7. أدوات القياس والتقييم والتقارير.
8. الاختبارات وتحسين الأداء وتجهيز الإطلاق.

## 9. معيار الإنجاز
لا تعتبر المرحلة مكتملة بمجرد إنشاء الواجهة. يجب توثيق الوظائف المنفذة وإعدادات الخدمات واختبارات البناء والوظائف والقيود المعروفة وطريقة التحقق.
