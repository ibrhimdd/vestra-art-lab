# PROJECT OVERVIEW — VESTRA ART LAB

## 1. تعريف المشروع
**الاسم:** VESTRA ART LAB  
**الوصف:** مختبر إبداعي فني رقمي متعدد التخصصات مدعوم بالذكاء الاصطناعي.  
**الفئة المستهدفة:** طلاب كلية التربية النوعية.  
**طبيعة الاستخدام:** تعليمي، إبداعي، تطبيقي، وبحثي.

يوفر المشروع بيئة رقمية موحدة يستطيع الطالب من خلالها استكشاف مجال فني، وتطوير فكرة تصميمية، وإنتاج بدائل، وتحليل العمل وتحسينه، ثم حفظ مراحل العمل ونتائجه.

## 2. المشكلة والاحتياج
تتوزع أدوات التعلم والإنتاج الفني بين تطبيقات متعددة، وقد يصعب تنظيم الأفكار ومراحل التجريب والنتائج في مساحة واحدة. كما أن استخدام الذكاء الاصطناعي دون توجيه تربوي قد يحول العملية إلى توليد نتائج جاهزة بدلاً من تنمية التفكير والتجريب.

يعالج VESTRA ART LAB هذا الاحتياج بربط مساحة العمل والمشروعات والأدوات الذكية والتقييم في تجربة تعليمية واحدة، مع إبقاء الطالب صاحب القرار الإبداعي.

## 3. الرؤية والأهداف
### الرؤية
أن يصبح المختبر بيئة جامعية رقمية داعمة للإبداع الفني والتصميمي والتعلم بالممارسة، وقابلة للتوسع إلى تخصصات وأدوات جديدة.

### الأهداف
- دعم إنتاج أعمال وتصميمات رقمية متعددة الأنماط.
- مساعدة الطالب على توليد بدائل بصرية واستكشاف أفكار جديدة.
- تحليل التصميمات وتقديم ملاحظات واقتراحات تطوير.
- تنظيم المشروعات ومراحل إنجازها وحفظها.
- توفير تجربة تعلم مرنة عبر الهاتف والحاسوب.
- دعم التقييم التربوي والبحثي من خلال بيانات واضحة ومصرح بها.

## 4. المجالات الفنية
1. **الملابس والنسيج:** أفكار الأزياء والألوان والنقوش وتنسيق القطع والتجربة الافتراضية.
2. **التربية الفنية:** الرسم والتكوين والتعبير البصري واستكشاف الأساليب.
3. **التصميم الرقمي:** الملصقات والهويات البصرية والتصميمات الرقمية.
4. **الفنون الزخرفية:** الوحدات الزخرفية والتكرارات والزخارف وتطبيقاتها.

يجب أن تكون المجالات قابلة للإضافة والتعديل دون إعادة بناء النظام بالكامل.

## 5. الوظائف الأساسية
### أ. الحسابات ومساحة الطالب
- إنشاء حساب وتسجيل الدخول والخروج.
- ملف شخصي ومساحة عمل خاصة.
- عرض المشروعات وحالتها وتواريخ تحديثها.

### ب. إدارة المشروعات
- إنشاء مشروع وربطه بمجال فني.
- حفظ وصف المشروع ومراحله وملفاته ونتائجه.
- إعادة فتح المشروع ومتابعة العمل عليه.
- التحكم في الخصوصية وفق الصلاحيات المعتمدة.

### ج. معمل التصميم
- رفع الصور والرسومات المرجعية.
- أدوات أولية لاستكشاف الألوان والنقوش.
- لوحات إلهام (Moodboards).
- مكتبة خامات وعناصر قابلة للتوسع.

### د. مساعد الذكاء الاصطناعي
- توليد أفكار وتصميمات أو بدائل انطلاقاً من وصف الطالب ومدخلاته.
- تحليل العمل وفق معايير واضحة يحددها المجال.
- تقديم ملاحظات واقتراحات قابلة للتنفيذ.
- توضيح أن المخرجات اقتراحات آلية وليست حكماً فنياً نهائياً.

### هـ. التجربة الافتراضية
- دمج تجربة الملابس الافتراضية الموجودة في المشروع السابق بعد مراجعة الكود والتراخيص والاعتماديات.
- حفظ مرجع القطعة ونتيجة التجربة ضمن مشروع الطالب عند الإمكان.
- عدم الادعاء بمحاكاة فيزيائية دقيقة للأقمشة أو المقاسات أو أجسام ثلاثية الأبعاد ما لم تتوفر الإمكانات فعلياً.

### و. القياس والتقييم
- اختبارات قبلية وبعدية عند اعتماد تصميم الدراسة.
- أدوات تقييم فني وفق rubrics واضحة.
- قياس الانخراط ومتابعة تقدم الطالب.
- تقارير فردية وإحصاءات مجمعة مع مراعاة الخصوصية.

## 6. القرارات التقنية المعتمدة
| المجال | القرار |
|---|---|
| واجهة المستخدم | React + Vite |
| قاعدة البيانات | Firebase / Cloud Firestore |
| المصادقة | Firebase Authentication |
| الملفات | Firebase Storage عند تهيئته |
| الذكاء الاصطناعي | Flexible provider adapter |
| اللغة والاتجاه | العربية وRTL مع قابلية دعم لغات أخرى |
| النشر | Vercel خيار مستهدف، ويؤكد بعد الإعداد |

### مبدأ مرونة مزود الذكاء الاصطناعي
يجب ألا تستدعي مكونات الواجهة مزوداً بعينه مباشرة. تمر الطلبات عبر واجهة خدمة داخلية موحدة، وتنفذ موصلات المزودين في طبقة آمنة على الخادم. تحفظ المفاتيح السرية في متغيرات بيئة خادمية فقط، ولا تستخدم متغيرات VITE_ للمفاتيح السرية.

## 7. مبادئ التصميم وتجربة الاستخدام
- واجهة عربية RTL واضحة ومتجاوبة.
- تصميم بصري متماسك يخدم الإبداع دون تشتيت.
- مكونات قابلة لإعادة الاستخدام.
- حالات تحميل وفراغ وخطأ ونجاح مفهومة.
- مراعاة سهولة الاستخدام وإمكانية الوصول.
- الحفاظ على ملكية الطالب لقراراته وأعماله.

## 8. الخصوصية والأمان
- وصول الطالب إلى بياناته ومشروعاته وفق قواعد صلاحيات موثقة.
- التحقق من الصلاحيات في قواعد Firebase والخادم، وليس في الواجهة فقط.
- عدم تخزين مفاتيح API أو بيانات Service Account في Git.
- توضيح ما إذا كانت الصور أو الملفات سترسل إلى مزود ذكاء اصطناعي خارجي.
- عدم استخدام أعمال الطلاب أو بياناتهم في أغراض أخرى دون أساس واضح وموافقة مناسبة.

## 9. مراحل التنفيذ المقترحة
1. تأسيس المشروع والهوية والهيكل والتوثيق.
2. الحسابات ومساحة الطالب وإدارة المشروعات.
3. معمل التصميم ورفع الملفات ومكتبة الخامات.
4. طبقة الذكاء الاصطناعي المرنة للتوليد والتحليل.
5. دمج تجربة الملابس الافتراضية.
6. أدوات القياس والتقييم والتقارير.
7. الاختبارات وتحسين الأداء وتجهيز الإطلاق.

لا تعتبر المرحلة مكتملة بمجرد إنشاء الواجهة. يجب توثيق الملفات والوظائف المنفذة، وإعدادات الخدمات، واختبارات البناء والوظائف، والقيود والأخطاء المعروفة، وطريقة التحقق، وتحديث PROJECT_STRUCTURE.md وPROJECT_STATUS.md.
